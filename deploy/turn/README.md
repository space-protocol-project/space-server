# Голосовые комнаты через интернет и NAT

Разработка после v0.6.0: нужен новый runtime и клиент из `codex/voice-rooms`, схема 23, `voice_rooms_version: "2"`. Выпущенный runtime v0.6.0 этой возможности не содержит.

## Как проходит соединение

Авторизованный клиент запрашивает конфигурацию ICE для конкретной голосовой комнаты. Runtime проверяет действующий допуск устройства и право слушать, выдаёт STUN/TURN URL и временные учётные данные. Общий TURN-секрет клиенту не передаётся. Имя временного пользователя случайное, без имени участника, principal/device ID или названия комнаты.

Клиент и runtime собирают кандидаты ICE: доступный адрес, внешний адрес через STUN или ретранслятор TURN. Поэтому TURN на публичном VPS может обслужить и домашний runtime за NAT/CGNAT. Публично доступный адрес API пространства всё равно необходим: TURN переносит медиа, а не HTTP API. Имеющийся HTTPS-проброс runtime остаётся отдельным механизмом.

TURN поддерживает UDP, TCP и TLS URL. Защитный режим `relay-only` запрещает прямые кандидаты с обеих сторон. Видео и запись не включаются; аудио остаётся WebRTC/Opus через runtime, без MLS/E2EE.

## Свой TURN на VPS

1. Нужен VPS с публичным IP. На Debian/Ubuntu установите `coturn` из поддерживаемого репозитория ОС: `sudo apt-get install coturn`.
2. Скопируйте [turnserver.conf.example](turnserver.conf.example) в `/etc/turnserver.conf`. Замените демонстрационный IP, домен и секрет. Получите случайный секрет командой `openssl rand -hex 32`; храните заполненную конфигурацию с ограниченным доступом и не отправляйте секрет в чат или Git.
3. Откройте UDP/TCP 3478 и UDP 49160–49259 в межсетевом экране VPS и панели провайдера. Это пример диапазона ретранслятора, а не медиа-портов runtime.
4. Для `turns:` установите сертификат доверенного центра для домена TURN, укажите `cert`/`pkey` и откройте TCP 5349. Закрытый ключ должен читаться службой coturn, но не всеми пользователями. Проверка сертификата в клиенте и runtime не отключается.
5. Запустите `sudo systemctl enable --now coturn`. Сверьте журнал `journalctl -u coturn`, адреса прослушивания и отсутствие ошибок конфигурации. Если сам VPS находится за NAT, настройте `external-ip=PUBLIC_IP/LOCAL_IP` и проброс тех же портов без изменения номеров.

Шаблон запрещает ретрансляцию во внутренние и служебные сети VPS, ограничивает число выделений и полосу. Не включайте анонимный TURN или разрешение loopback в рабочей конфигурации. Если runtime и TURN находятся на одном VPS, runtime должен публиковать доступный внешний адрес либо использовать собственный relay-кандидат; внутренние адреса блокируются намеренно.

## Настройка runtime

Создайте на компьютере runtime защищённый текстовый файл с тем же общим секретом, который задан в coturn. Переменные окружения процесса:

```text
SPACE_VOICE_STUN_URLS=stun:voice.example.org:3478
SPACE_VOICE_TURN_URLS=turn:voice.example.org:3478?transport=udp,turn:voice.example.org:3478?transport=tcp,turns:voice.example.org:5349?transport=tcp
SPACE_VOICE_TURN_SECRET_FILE=/private/path/turn-secret
SPACE_VOICE_RELAY_ONLY=false
```

Удалите `turns:` из списка, пока TLS не настроен. В Windows путь к файлу может быть, например, `C:\Space\private\turn-secret`; задайте переменные перед запуском приложения или runtime. Для systemd добавьте их в `EnvironmentFile` службы runtime и перезапустите службу. Для домашнего runtime, запускаемого приложением, переменные должны быть в окружении самого приложения.

Вместо файла поддерживается `SPACE_VOICE_TURN_SECRET`, но одновременно два источника запрещены. Файл предпочтительнее. Секрет не нужно указывать в аргументах процесса. Конфигурация проверяется при запуске; ошибочная настройка не заменяется молча локальным режимом.

Для домашнего runtime за CGNAT начните с `SPACE_VOICE_RELAY_ONLY=true`: все участники и runtime используют TURN, входящие UDP-порты на домашнем роутере не требуются. При запрете исходящего UDP используйте только `turn:voice.example.org:3478?transport=tcp` или `turns:voice.example.org:5349?transport=tcp`. HTTPS API должен оставаться доступным.

Временный пароль действует 24 часа. Он является доступом к ретранслятору: не сохраняйте его в журналах. Отзыв участника закрывает его медиасеанс runtime; уже выданные учётные данные самого внешнего TURN действуют до своего срока, поэтому квоты coturn обязательны. Ротация общего секрета требует согласованного перезапуска и повторного входа в разговор. Непрерывный разговор дольше 24 часов и автоматическое ICE-переподключение пока не поддерживаются.

## Прямой маршрут с известным публичным IP

Для VPS с прямым IP без NAT достаточно доступных UDP-портов. При обычном NAT с неизменными номерами портов можно задать:

```text
SPACE_VOICE_PUBLIC_IP=203.0.113.20
SPACE_VOICE_UDP_MIN=40000
SPACE_VOICE_UDP_MAX=40127
```

Замените IP настоящим адресом; откройте и пробросьте диапазон UDP на этот runtime без смены номеров. При смене IP перезапустите runtime с новым значением и войдите в комнату снова. Для динамических адресов предпочтительнее STUN/TURN. Автоматический проброс медиа-диапазона через UPnP не реализован: существующий проброс HTTPS не открывает UDP для WebRTC. У CGNAT ручной публичный IP этот маршрут не создаёт.

## Что проверяется

`TestTwoClientsForcedThroughTURN` устанавливает настоящие ICE/DTLS/SRTP-соединения через loopback TURN отдельно по UDP и TCP. И клиенты, и runtime используют relay-only: в SDP нет прямых кандидатов, проверяются четыре TURN-выделения и RTP в обе стороны. Также проверяются авторизация выдачи паролей, совместимость TURN REST, отзыв доступа и отказ при ошибочной конфигурации.

В `space-app/tools/check_voice_rooms.ps1` режимы `-Relay udp` и `-Relay tcp` запускают два независимых Windows-клиента с настоящим микрофоном и нативным WebRTC. Тестовый TURN привязан к одному частному интерфейсу этого компьютера, требует случайный секрет и разрешает ретрансляцию только на тот же IP. Публичный интерфейс для него запрещён; это не рабочий TURN-сервер. Качество звука между людьми, работа с реальным провайдером/CGNAT и TURN/TLS с доверенным публичным сертификатом требуют отдельной внешней проверки. VPS для неё пока не предоставлен.

Основание параметров и формата паролей: [официальная конфигурация coturn](https://github.com/coturn/coturn/blob/master/examples/etc/turnserver.conf), [TURN REST coturn](https://github.com/coturn/coturn/blob/master/README.turnserver), [Pion TURN](https://pkg.go.dev/github.com/pion/turn/v5).
