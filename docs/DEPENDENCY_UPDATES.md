# Обновление SDK и зависимостей — 23 октября 2026

Go 1.27.3 — актуальный стабильный выпуск по [официальной истории Go](https://go.dev/doc/devel/release#go1.27.0). Он уже был закреплён в `go.mod`; CI выбирает его через `go-version-file`, а упаковщик сверяет версию внутри собранного сервера с `go.mod`.

На рабочей машине общая команда `go` теперь выбирает 1.27.3 через `go env -w GOTOOLCHAIN=go1.27.3+auto`. Это штатный [механизм toolchain](https://go.dev/doc/toolchain), сохраняющий возможность использовать более новый SDK по требованию проекта.

## Зависимости

Выполнены `go get -u ./...` и `go mod tidy`; обновлены 20 зависимостей, `go.mod` и `go.sum` сохранены вместе. Основные версии:

| Компонент | До | После |
|---|---|---|
| Connect и генератор Connect-Go | 1.19.2 | 1.21.1 |
| gRPC | 1.83.2 | 1.84.0 |
| grpc-gateway | 2.26.3 | 2.32.0 |
| pgx | 5.9.2 | 5.11.0 |
| Pion WebRTC | 4.2.24 | 4.2.25 |
| protobuf | 1.36.11 | 1.36.12 |
| x/crypto | 0.57.0 | 0.58.0 |
| x/net | 0.60.0 | 0.61.0 |
| x/sys | 0.48.0 | 0.49.0 |

Обновлены также совместимые Pion DTLS/ICE/interceptor/RTP/RTCP, puddle, x/sync, x/text, x/time и genproto. Генерация через `buf.connect.gen.yaml` прошла; содержимое сгенерированных файлов не изменилось.

После обновления `go list -m -u -json all` сопоставлен с модулями из `go list -deps -test ./...`: среди модулей, чьи пакеты импортируют сервер и его тесты, оставшихся обновлений нет. Ещё 25 более новых версий видны только в полном графе зависимостей чужих модулей; их пакеты сервер и его тесты не импортируют. Принудительные требования к этим неиспользуемым модулям не добавлялись.

В серверных workflow Flutter 3.47.7 заменён на 3.47.8, соответствующий обновлению клиента. PostgreSQL в Compose и CI обновлён с 17.6 до 17.11 — той же версии, что уже используется упаковщиком runtime. Ветка PostgreSQL остаётся 17; установленная пользовательская база не обновлялась. Сведения о [PostgreSQL 17.11](https://www.postgresql.org/docs/release/17.11/).

## Проверка

- Проверочный Windows runtime составлен из нового сервера, собранного с Go 1.27.3, и неизменённых бинарных файлов PostgreSQL 17.11 из уже установленного комплекта, подключённых через junction. `-runtime-info` подтверждает PostgreSQL major 17, схему 30 и голосовой профиль 3. Новый архив для публикации не упаковывался.
- `go vet ./...`, `go mod verify` и actionlint изменённых workflow прошли.
- Тесты упаковщика: 11 успешно, 7 пропущено по условиям окружения.
- `govulncheck`: 0 уязвимостей вызываемого кода и 0 в импортируемых пакетах. На уровне модулей есть [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) для неиспользуемого `x/crypto/openpgp`; исправленной версии для него нет. Сам OpenPGP сервер не импортирует.
- Сквозной `home_server_drill.dart` прошёл с новым сервером и PostgreSQL 17.11: владелец, TLS/Connect, pin, приглашение, ACL, сообщение, перезапуск; также проверены диагностика, смена адресов, домен/IPv6, прежнее устройство, MLS leaf, очередь и зашифрованный файл.
- Полный `go test -race -p 1 -json -count=1 -timeout=15m ./...` с отдельной PostgreSQL 17.11 и `SPACE_HOME_RUNTIME`: **332 теста прошли, ошибок и пропущенных тестов нет**, 11 пакетов прошли, 5 пакетов не содержат тестов. Включены резервное копирование/восстановление, перенос пространства, сохранность данных и идентичности, схема 30, форум, ACL, история, поиск, транспорт и голос.
- При первом параллельном прогоне тест резервного копирования упёрся в тайм-аут `initdb` во время синхронизации на диск. В последовательном полном прогоне с `-race` он прошёл за 19,5 секунды; проверки и тайм-ауты кода не ослаблялись.

Это локальная проверка Windows. Сборки и приёмка Linux/macOS, реальный публичный TURN, акустические испытания и доступность из другой сети в неё не входят. Выпуск runtime и переключение установленного пространства не выполнялись.
