# Ограниченная нагрузка P1

Профиль фиксируется до запуска. Три независимых Linux CI runner, каждый с собственной PostgreSQL 17.11. Фазы по 300 секунд: 1, 2 и 8 клиентов; первые 60 секунд каждой фазы исключаются из распределений. Случайность не используется: seed отсутствует, расписание детерминировано номером операции. После каждой операции пауза 20 мс, квоты и deadline исполнителя не меняются.

Набор: одна установка, 360 заранее зарегистрированных экземпляров для трёх фаз и восьми клиентов (15 слотов на клиента), контрольный `demo`, независимый `other` на другом канале и `quota`, отдельный `revocation` на своём канале. Каждые 20 секунд клиент переходит на следующий слот. Первый успешный вызов фиксированного WASM-плана переводит ревизию 0 → 1, пишет один ключ и одно событие. Последующие команды с тем же ключом сверяют квитанцию. Это ограниченный набор, без удаления квитанций или данных во время нагрузки.

Цикл из восьми операций: query, уникальная команда либо её повтор, replay, конфликт байтов payload, конфликт ревизии, заранее отменённый query, команда с недопустимым stateless-эффектом и повтор ранее успешной команды независимого экземпляра. До первой успешной записи конфликт payload заменяется повтором исходной команды. Ожидаемые коды: OK, ResourceExhausted при занятом бюджете; AlreadyExists для конфликта payload; Aborted для ревизии; Canceled для отмены; InvalidArgument для недопустимого эффекта; DeadlineExceeded только для query при исчерпании прежнего бюджета, отдельно от успешных ответов. Для команд такой код не допускается. Другие ошибки проваливают приёмку. Отмена уже исполняющегося вызова проверяется отдельными детерминированными тестами ядра.

До нагрузки проверяются ACL и блокировка участника. Во время каждой фазы на отдельном экземпляре `revocation` повторяется отзыв ACL/членства и проверяется PermissionDenied. Владелец продолжает независимые запросы; гонки отзыва между WASM и COMMIT остаются обязательной отдельной матрицей ядра. До нагрузки `quota` явно заполняется 1024 тестовыми квитанциями: следующая запись отклоняется, команда `other` успешна. Эти строки сохраняются до конца; финальная сверка отдельно исключает подготовленные квитанции.

Все запросы проходят настоящий gRPC, сессии ядра, dispatcher и ProcessHost; WASM компилируется/исполняется отдельным процессом. Бюджет ProcessHost 512 МиБ, worker 256 МиБ, deadline 2 с. Старый внутренний профиль регистрации разрешает только собственные данные и `note_changed`; гостю не выдаются ядро, сеть или каталог устройства. Полный manifest со stateless-формами проверяется отдельным профилем и не используется для обхода запрета мутаций.

`requests.jsonl` содержит фазу, клиента, операцию, код, задержку и признак прогрева. `summary.json` содержит p50/p95/p99 и число запросов в секунду по фазе/операции/коду. `resources.jsonl` каждые 5 секунд фиксирует RSS/HWM процесса тестового сервера, cgroup CPU/память/OOM/процессы/резервирование, число ожидающих SQL-блокировки соединений, суммарное ожидание получения соединения пула и размер данных/квитанций/outbox. Ожидание пула не объявляется временем блокировок SQL; RSS включает gRPC-клиентов и race-инструментацию в том же процессе.

После остановки клиентов проверяются нулевые активные вызовы/резервирование/процессы, точное равенство числа успешных первых команд ревизиям, данным, квитанциям и событиям, контрольная команда, закрытие хоста с проверкой отсутствия оставшихся cgroup и освобождение пула. Публикуются исходные значения, а не SLA продукта. Неуспешный прогон требует исправления и повторной полной приёмки.

Перед каждой пятиминутной фазой выполняется настоящий challenge/signature вход тем же владельцем и устройством. Это не продление строки сессии в БД: прежний десятиминутный срок жизни сохраняется. Первый прогон 42993902053 выявил истечение исходной сессии на третьей фазе и не засчитывается; повтор выполняет все три фазы заново.

Прогон 42996869228 не принят: стенд ошибочно ожидал stateless-команду от mutation-регистрации и проверял удаление группы хоста до Close. Исправление сохраняет отказ InvalidArgument и проверяет удаление после закрытия. Независимый экземпляр получает настоящий повтор mutation-команды. Журнал запросов сохраняется также при отказе итоговых проверок.

Прогон 43000234510 выявил предусмотренный отказ query при изменении ревизии ACL его канала между проверками допуска: сравнение AccessStamp отклоняет даже запрос владельца. Нагрузочный контроль отзыва перенесён на собственный канал/экземпляр, чтобы измерять независимую работу остальных запросов. PermissionDenied не добавлен к допустимым кодам основной нагрузки. Гонки на одном канале по-прежнему покрывает отдельная детерминированная матрица ядра.

В 43002228366 два задания успешны, третье выявило неверную классификацию двухсекундного тайм-аута авторизации как PermissionDenied. Dispatcher и адаптер PostgreSQL теперь сохраняют DeadlineExceeded/Canceled, не выдавая ответ гостя; прочие ошибки по-прежнему не раскрывают детали. Новый обязательный тест удерживает настоящую таблицу сессий после вызова, требует DeadlineExceeded без ответа и успешный свежий запрос после освобождения блокировки. Нагрузочный профиль учитывает исчерпание бюджета query отдельно, не как успех; тайм-аут и квоты не повышены. Результат ошибочной классификации не засчитывается.
