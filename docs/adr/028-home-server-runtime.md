# ADR-028: домашний сервер из основного приложения

Дата: 10 октября 2026 года. Статус: экспериментальная реализация, проверки и ограничения — в руководстве домашнего сервера.

## Решение

«Выйти в эфир» означает запуск сохранённого домашнего сервера; это не создание медиа-трансляции. Один профиль приложения содержит один сервер. Повторный запуск сохраняет PostgreSQL, server ID, ключи, сертификат и разрешения. После запуска действие называется «Отключиться» и останавливает процессы с сохранением данных.

По последнему требованию пользователя выбран статический публичный IPv4 без домена. Сертификат создаётся локально и сохраняется; внешние HTTPS и HTTP/2 gRPC используют порт 8443. Самоподписанный сертификат закрепляется в Space; отпечаток передаётся в приглашении. Проверка сертификата не отключается глобально. Первичное доверие без отпечатка остаётся подтверждаемым TOFU.

PostgreSQL поставляется вместе с сервером отдельным платформенным выпуском и запускается в профиле пользователя. Это отдельный кластер, без системного сервиса и Docker. Пароль случайный, база слушает только loopback и требует SCRAM. Каталог данных независим от каталога бинарников. Выпуск загружается с фиксированного адреса GitHub Releases и проверяется по SHA-256, закреплённому в приложении. Архивы с выходом за пределы каталога, ссылками или превышением лимита отклоняются до распаковки.

Первый владелец назначается локально: перед внешним запуском создаётся ручной setup-код, клиент использует публичный origin для подписей, но локальный маршрут для транспорта. До назначения владельца все внешние HTTP/gRPC запросы получают отказ. Локальные эндпоинты не пробрасываются наружу. После настройки внешний доступ использует те же сервисы, роли и ACL, что и обычный сервер.

Управляющее приложение держит stdin сервера открытым. Закрытие канала инициирует штатное завершение и остановку PostgreSQL. Блокировка каталога предотвращает параллельный запуск из другого экземпляра приложения. Установленный выпуск повторно не скачивается. Публичная ссылка не предоставляет прав владельца; управление остаётся в общем Flutter-модуле.

## Проверки и границы

Проверяются SHA-256 и безопасная распаковка, TLS-пин и сохранение доверия, смена надписи кнопки, повторный запуск базы и сертификата. Сквозной сценарий runner проверяет закрытый внешний вход до owner, ручное локальное назначение owner, приглашение друга по TLS/gRPC, сохранённое сообщение и повторный запуск с прежним server ID.

Runner не доказывает доступность через домашний роутер: внешний интернет, сон компьютера и брандмауэр проверяются вручную. Смена IP, восстановление после принудительного убийства, резервное копирование и обновление кластера требуют следующих этапов. Нельзя считать сертификат или QR-карточку резервной копией серверной базы.
